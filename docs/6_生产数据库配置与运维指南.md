# 6. 生产数据库（Neon）配置与运维指南

> 适用场景：首次配置生产数据库、日常数据更新、排障。
> 选用平台：**Neon**（serverless PostgreSQL），站点通过 Vercel 环境变量 `DATABASE_URL` 连接。
> 相关代码：前端 Drizzle 客户端 `src/lib/db/client.ts`；pipeline 发布 `pipeline/publish/`；迁移 `drizzle/`。

## 总体架构

```
本地 pipeline（每日 17:30 定时任务）
   │  Stage 5 publish（psycopg，Direct 连接）
   ▼
Neon PostgreSQL（生产库，站点唯一数据源）
   ▲
   │  Drizzle（postgres.js 驱动，Pooled 连接）
Vercel（Next.js 站点，只读）
```

要点：

- pipeline 仍在本地运行，只是 publish 的写入目标从本地 Docker 换成 Neon。
- Vercel 端只需要一个环境变量 `DATABASE_URL`，前端 `client.ts` 已设 `prepare: false`，兼容 Neon pooler，无需改代码。
- 本地 `data/` 目录已 gitignore，不会也不应提交到仓库；它仍是 pipeline 的本地工作存储（含文章全文），站点不读它。

## 两个连接串，别用混

Neon 每个项目提供两种连接串：

| 连接串 | 主机名特征 | 用途 |
|--------|-----------|------|
| **Pooled** | 带 `-pooler` | Vercel 环境变量（pgBouncer 池化，适合 serverless 高并发短连接） |
| **Direct** | 不带 `-pooler` | 本地 drizzle 迁移建表 + pipeline publish 写入（pooler 事务模式可能干扰 DDL） |

连接串形如：`postgresql://<user>:<password>@<host>.neon.tech/<dbname>?sslmode=require`

## 一、首次配置（一次性）

### 第 1 步：创建 Neon 项目（约 5 分钟）

1. 打开 **console.neon.tech**，用 GitHub 账号登录。
2. **Create project**：项目名如 `ai-insight`；区域选离 Vercel 部署区域最近的（Vercel 默认美东 → 选 `US East (N. Virginia)`）。
3. 创建完成后在 Dashboard **复制 Pooled 和 Direct 两条连接串**，妥善保存。

### 第 2 步：建表（drizzle 迁移）

在仓库根目录执行，用 **Direct 端点**：

```bash
DATABASE_URL="postgresql://<user>:<pass>@<host>.neon.tech/<db>?sslmode=require" \
  pnpm drizzle-kit migrate
```

迁移文件 `drizzle/0000_powerful_yellow_claw.sql` 已在仓库中，会创建 `daily_reports` / `manifests` / `articles` 三张表。

### 第 3 步：回填历史数据

把本地 `data/` 的存量数据灌进 Neon，同样用 **Direct 端点**：

```bash
DATABASE_URL="postgresql://<user>:<pass>@<host>.neon.tech/<db>?sslmode=require" \
  uv run python pipeline/run.py publish --force
```

`--force` 会合并 archive 冷数据分片做全量回填。跑完后核验：日报数 ≈ `ls data/05_reports/daily-report-*.json | wc -l`，文章数 ≈ `data/04_structured/` 热数据 + archive 分片去重后的总数。

### 第 4 步：配置 Vercel 环境变量

Vercel 项目 → **Settings → Environment Variables**：

| 变量 | 值 | 环境 |
|------|-----|------|
| `DATABASE_URL` | **Pooled** 连接串 | Production + Preview |

保存后 **Redeploy**（环境变量改动需要重新部署才生效）。

### 第 5 步：本地 .env 策略

本地 `.env` 的 `DATABASE_URL` 二选一：

- **方案 A（推荐，简单）**：直接指向 Neon（Direct 端点 + `sslmode=require`）。每日定时 pipeline 跑完自动 publish 直写生产库；本地 `pnpm dev` 也读 Neon，所见即生产。
- **方案 B（隔离）**：保持指向本地 Docker 做开发，只在发布时用环境变量前缀单次覆盖（见下文"手动发布"）。

### 本地开发提速：.env.development.local（强烈推荐）

方案 A 有个明显副作用：本地 `pnpm dev` 的每次页面渲染都要跨国查询 Neon（美东），单条查询可达 30s+，页面会一直卡在骨架屏。解法是新增 **`.env.development.local`**（已 gitignore），仅 dev 模式生效：

```bash
# .env.development.local — Next.js dev 加载顺序：.env.development.local > .env
DATABASE_URL=postgresql://postgres:postgres@localhost:5433/ai_insight
```

效果分工：

- `pnpm dev` → 读本地 Docker PG，页面渲染毫秒级
- pipeline（publish / 定时任务）→ python-dotenv 只读 `.env`，仍写 Neon 生产库，互不影响

本地库数据同步（幂等，需要时执行）：

```bash
DATABASE_URL="postgresql://postgres:postgres@localhost:5433/ai_insight" \
  uv run python pipeline/run.py publish --force
```

### 验证清单（部署后逐项检查）

1. `/dashboard` — 日报卡片列表数量与回填报告数一致
2. `/dashboard/[date]` — 最新一天仪表盘图表正常渲染
3. `/report/[date]` — Markdown 全文正常
4. `/` 和 `/sources/[name]` — 信源清单与文章列表有数据
5. `/specialized/github/[date]` 等专题页正常

## 二、日常数据更新

### 每日自动更新（默认路径）

每日 17:30 定时任务跑 scout/ingest，随后按 daily-report-pipeline 流程（check → repair → extract → analyze → synthesize）执行，synthesize 成功后**自动 publish** 到 `DATABASE_URL` 指向的库，末尾还有一条幂等 `publish --target-date` 兜底。

只要 `.env` 的 `DATABASE_URL` 指向 Neon（方案 A），整个过程无需人工干预，站点实时可见。

### 手动发布某一天

已跑过 pipeline、只需把某天的数据同步到生产库（publish 幂等，可重复执行）：

```bash
uv run python pipeline/run.py publish --target-date 2026-10-10
```

如 `.env` 指向本地库、只想发一次到生产，用前缀覆盖：

```bash
DATABASE_URL="postgresql://<user>:<pass>@<host>.neon.tech/<db>?sslmode=require" \
  uv run python pipeline/run.py publish --target-date 2026-10-10
```

### 补跑某天的完整日报

使用 run-report / daily-report-pipeline 技能（从抓取完整性检查开始，门禁式跑通 extract → analyze → synthesize → publish），所有操作严格限定 `created == 目标日期`，不影响其他日期数据。详见 `.agents/skills/daily-report-pipeline/SKILL.md`。

### 全量重灌（慎用）

数据库被清空、迁移重建或需要冷数据全量回填时：

```bash
DATABASE_URL="<Neon Direct 连接串>" uv run python pipeline/run.py publish --force
```

publish 是幂等 upsert（ON CONFLICT），重复执行不会产生重复数据，但全量耗时较长。

## 三、注意事项与排障

- **密钥管理**：连接串含密码，只放 Vercel 环境变量和本地 `.env`（已 gitignore），绝不提交到仓库。
- **站点 500 / 页面报错**：先查 Vercel 环境变量 `DATABASE_URL` 是否配置、是否用的是 Pooled 连接串、改完后是否 Redeploy。
- **迁移失败**：确认用的是 Direct 端点而非 Pooled。
- **publish 报 DATABASE_URL 未配置**：pipeline 从 `.env` 加载（`pipeline/run.py` 自动加载），检查 `.env` 或用前缀注入。
- **首次访问慢 1-2 秒**：Neon 免费档自动休眠冷启动，属正常现象。
- **免费档限额**：0.5 GB 存储。逼近上限时可缩短 `config.yaml` 的 `stages.aggregate.max_history_days`（默认 365 天）减少冷数据，或升级档位。
- **数据不一致排查**：以 DB 行数核验作为"站点可见"的判据（见 daily-report-pipeline skill 的 DB 核验步骤）。
