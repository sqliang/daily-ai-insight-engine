## 1. 项目定位

Daily AI Insight Engine 是一套面向 AI 行业决策者（投资人、产品负责人、工程管理者）的**日报级情报合成系统**。它从 19 个中英文信源自动采集每日 AI 资讯，经过四阶段流水线处理（采集 → 事实提取 → 深度分析 → 综合合成），最终生成一份包含 Top 事件、深度研判、趋势判断、风险与机会信号的完整日报，并通过 Next.js 看板进行交互式可视化。

**核心价值主张**：

- **信源覆盖**：跨学术论文、技术博客、科技媒体、社区讨论四大类型，中英文双语
- **分析深度**：三视角并行深度研判（技术架构师、资本分析师、风控专家），每篇文章产出 32+ 结构化字段
- **自动化**：全流程 Python 异步流水线，支持断点续传、错误重试、并发控制
- **可审计**：每阶段产物以 Markdown + YAML Frontmatter 持久化，支持人工抽查和回滚重跑
- **可视化**：Next.js 看板零聚合渲染，直接读取最终 JSON 报告

**关键设计决策**：

1. **离线流水线 + 静态文件桥接**：Pipeline 输出 JSON 文件，前端通过 `readFile()` 直接读取，无 API 层、无数据库、无网络请求。这意味着：零冷启动、无需后端服务、部署即静态站点
2. **Markdown 贯穿全流程**：每个阶段的产物都是可读的 `.md` 文件，YAML Frontmatter 逐阶段叠加字段，支持任意阶段回滚重跑
3. **两阶段并行策略**：外层级 `asyncio.Semaphore` 控制文件级并发，内层级 `asyncio.gather` 控制单文件三评估维度并行

**目录命名约定**：数字前缀 `0X_` 对应流水线阶段，方便按序理解数据演化：
- `00` — 发现（Scout 产出）
- `01` — 摄入（原始清洗文本）
- `02` — 提取（事实层）
- `03` — 分析（洞察层）
- `04` — 结构化（Stage 4a 中间产物）
- `05` — 报告（Stage 4b 最终产出）

## 4. 四阶段流水线

### Stage 1 — 数据采集 (Ingestion)

**目标**：从 19 个信源自动获取当日 AI 资讯，输出干净的 Markdown 文件。

**两步骤流程**：

| 步骤 | 名称 | 职责 | 输出 |
|------|------|------|------|
| 1a | **Scout** | 从信源抓取 URL 列表，按过滤规则筛选，生成 Manifest JSON | `data/00_manifest/{source}_{date}.json` |
| 1b | **Ingest** | 读取 Manifest，逐 URL 下载全文、清洗 HTML、生成 Markdown | `data/01_raw/{source}/*.md` |

**四种抓取策略**：
- `rss` — RSS/Atom feed（feedparser 解析），覆盖 arxiv、OpenAI、HN、TechCrunch 等
- `api` — 直接调用 JSON API（如 TLDR AI）
- `scrape` — HTML 解析（BeautifulSoup + name-based parser registry），覆盖 Anthropic sitemap 等
- `browser` — 无头浏览器渲染（Playwright），覆盖知乎、机器之心等 SPA 页面

**过滤管线**：关键词匹配 → 时间窗口（max_age_hours） → 数量上限（max_articles_per_source） → URL 去重 → 标题相似度去重

详见：[1_数据源筛选与获取设计说明.md](./1_数据源筛选与获取设计说明.md)

---

### Stage 2 — 事实提取 (Fact Extraction)

**目标**：从每篇文章的正文中提取结构化事实，写入 YAML Frontmatter。

**提取内容**（2 个 Block）：
- **Block 0: BaseInfo** — 物理可溯源信息：`id`（SHA-256 of source URL）、`source_type`（信源类型枚举）
- **Block 1: FactExtraction** — 信息压缩：`tldr`、`objective_summary`、`event_type`、`epistemic_status`、`entities`（公司/技术/人物/产品/地区）、`key_logic_flow`（关键逻辑脉络 3-6 条）、`impact_score`（1-10）

**技术特点**：
- 使用 `claude-sonnet-4-6`（temperature 0.1, max_tokens 4096），追求速度与准确性平衡
- Enum 模糊匹配 + 交叉交换修复（LLM 错将相邻枚举值互换时的自动纠正）
- 正文智能截断（`truncate_at_natural_break`，在段落边界处截断以保持语义完整）
- `skip_existing` 模式：已有完整前端的文件跳过，支持断点续传

---

### Stage 3 — 深度分析 (Deep Analysis)

**目标**：从三个互补视角对每篇文章进行深度研判，三评估维度并行执行。

| 视角 | 评估维度 | 核心字段 | 角色定位 |
|------|----------|----------|----------|
| Tech Architect | `QualitativeAssessment` | `impact_score`, `sentiment`, `developer_sentiment`, `hype_assessment`, `information_entropy`, `domain_disruption`, `engineering_complexity` | 短期技术研判 |
| Capital Analyst | `ValueAssessment` | `compound_value`, `value_capture_layer`, `moat_impact`, `key_beneficiaries`, `competitive_casualty` | 长期价值评估 |
| Risk Assessor | `ForesightAndActionability` | `market_opportunities`, `risk_matrix`, `confidence`, `actionable_insight` | 前瞻行动指引 |

**并行策略**：
- 外层级 `asyncio.Semaphore(3)` 控制同时处理的文件数
- 内层级 `asyncio.gather` 对单文件的三维度同时调用 LLM
- 失败隔离：单个维度失败不影响其他维度写入

**LLM 配置**：`claude-opus-4-7`（temperature 0.3, max_tokens 8192），追求分析深度

---

### Stage 4 — 综合合成 (Synthesis)

**Stage 4a — Frontmatter 聚合（机械操作）**：

- 递归扫描 `data/03_analyzed/` 下所有 `.md` 文件
- 提取 YAML Frontmatter（不含正文 body）
- 按数据源分组输出 `{source}.json`
- 合并为 `all_articles.json`（含源级统计摘要：avg_impact）
- **零 LLM 调用，< 1 秒完成**

**Stage 4b — Editor-in-Chief 合成（单次 LLM 调用）**：

- 读取 `all_articles.json`（244 篇文章）
- 构造两段 Prompt：
  - **System Prompt**：定义角色（AI 行业情报主编）、完整 JSON 输出 Schema、9 条质控规则
  - **User Prompt**：三部分结构 — ① 预计算统计概览（事件类型分布、情绪分布、实体频次等）+ ② Top 30 文章完整 Frontmatter（按 impactScore 降序）+ ③ 剩余文章标题列表
- 单次 `claude-opus-4-7` 调用（~38K tokens），输出完整日报 JSON
- 写入 `daily-report.json` + `daily-report.md`

**日报包含**：
- Top 5 事件（含支撑证据、影响力评分、为什么重要）
- 3 篇深度研判（背景、影响、后续关注）
- 4 维度趋势判断（技术、应用、政策、资本）
- 风险信号 4-7 条 + 机会信号 4-7 条
- 预计算的可视化数据（前端零聚合渲染）

## 6. 黄金三角信源体系

信源按"黄金三角"三层体系组织，确保学术前沿、开发者生态、商业落地三维覆盖：

```
                  顶点 A: 技术前沿
              arXiv, OpenAI, DeepMind,
              Anthropic, NVIDIA, HuggingFace
                     ╱  ╲
                    ╱    ╲
                   ╱      ╲
                  ╱  日报  ╲
                 ╱  视角   ╲
                ╱           ╲
               ╱             ╲
   顶点 B: 产品与开发者        顶点 C: 商业与资本
   HN, ProductHunt,          TechCrunch, The Verge,
   GitHub Trending,          KDnuggets, TLDR AI,
   Ben's Bites, 知乎         机器之心, 量子位, 36氪
```

**Tier 等级**：A（学术/技术，6 个信源）→ B（产品/社区，5 个信源）→ C（商业/资本，8 个信源）

**配额控制**：每 Tier 上限 5 篇，总目标 15 篇，超出按 impact_score 淘汰

## 7. 数据契约与 Schema 分层

### 7.1 Schema 架构

整个流水线的数据结构分为 **两阶段、五 Block**：

```
Phase 1: 事实层（Stage 2 产出）
├── Block 0: BaseInfo       — 物理可溯源（id, source_type）
└── Block 1: FactExtraction — 信息压缩（event_type, entities, key_logic_flow）

Phase 2: 研判层（Stage 3 产出，三维并行）
├── Block 2: QualitativeAssessment — 短期技术研判
├── Block 3: ValueAssessment       — 长期价值评估
└── Block 4: ForesightAndActionability — 前瞻行动指引
```

### 7.2 双端 Schema 对齐

| 端 | 技术 | 角色 |
|----|------|------|
| Python (pipeline/schemas/) | Pydantic v2 | **权威数据源** — LLM 输出校验、枚举定义 |
| TypeScript (src/lib/agent/schema.ts) | Zod | **前端消费端** — 日报 JSON 校验、TypeScript 类型推导 |

**关键对齐点**：
- `eventTypeSchema`：5 个值（`infrastructure_update`, `framework_tools`, `capital_movement`, `application_landing`, `policy_and_safety`），Python 定义、TypeScript 同步
- `sentimentDistribution` labels：4 个（`positive`, `neutral`, `negative`, `mixed`）
- `entityFrequency` type：5 个（`company`, `technology`, `person`, `product`, `region`）

详见：[2_Schema设计说明.md](./2_Schema设计说明.md)

## 8. 前端可视化设计

### 8.1 页面架构

| 页面 | 路由 | 数据来源 |
|------|------|----------|
| Sources | `/` | `pipeline/config.yaml` + `data/00_manifest/*.json` — 信源全景（首页） |

| Dashboard | `/dashboard` | `data/05_reports/daily-report.json` — 直接 `readFile()` |

### 8.2 组件树

**Dashboard 页 (`/dashboard`)**：
```
dashboard/page.tsx (Server Component, force-dynamic)
├── ReportHeader        — 日报标题 + 日期 + 执行摘要（glass panel）
├── KPISection           — 三张指标卡片（样本量 / 信源数 / 语言覆盖）
├── DistributionSection  — 双 Donut 饼图（事件类型 × 情绪分布）
├── TopEventsSection     — 5 大事件卡片（含证据列表 + 影响力评分）
├── RankingsSection      — 双栏（影响力排名 Bar × 高频实体 Bar）
├── TrendInsightsSection — 4 维度趋势卡片（T/A/P/C 标签）
├── DeepDivesSection     — 3 篇深度研判（背景 → 影响 → 后续关注）
├── SignalList × 2       — 风险信号 + 机会信号（严重程度标签）
└── ReportFooter         — 信源说明
```

**Sources 页 (`/`, 首页)**：
```
page.tsx (Server Component, force-dynamic)
├── SourcesHero          — 深色渐变 Banner: 标题 + 三角顶点卡片 + 统计 + 筛选策略
└── SourcesGrid          — 按 Tier 分组
    └── TierSection × 3  — A/B/C 区域（彩色竖条标题 + 卡片网格）
        └── SourceCard   — 单源卡片（标签/描述/关键词/文章数）
```

**Source Detail 页 (`/sources/[name]`)**：
```
sources/[name]/page.tsx (Server Component, force-dynamic)
├── Hero Banner          — 深色渐变（Tier 颜色差异化）+ 元数据胶囊 + 描述面板
└── ArticleList          — 可排序文章列表 (Client Component, impact score 排序切换)
    └── ArticleCard      — 文章卡片（标题/摘要/分析子卡片）
```

### 8.3 设计原则

- **零聚合**：所有图表数据由 Pipeline 预计算（`visualizationData` 字段），前端纯展示
- **force-dynamic**：禁用静态生成，每次请求重新读取文件
- **Zod 校验**：服务端渲染前先校验 JSON 结构，不合规直接抛错，不渲染损坏页面
- **深色主题**：全局 dark mode 仪表盘风格，glass morphism 面板效果
- **配置驱动 UI**：Sources 页面的展示文案（Tier 标签/副标题、源显示名称/描述）由 `config.yaml` 的 `tiers_meta` 和 `display_name`/`display_description` 字段驱动，无需修改组件代码
- **骨架屏**：首页和 Dashboard 页均有精确定位骨架屏（`loading.tsx`），与真实页面结构一一对应，无视觉跳跃

## 9. 运维与可观测性

### 9.1 运行命令

```bash
# Stage 1: 采集
python pipeline/run.py scout          # 生成 URL 清单
python pipeline/run.py ingest         # 下载清洗正文

# Stage 2: 事实提取
python pipeline/run.py extract        # 全部文件
python pipeline/run.py extract --force   # 强制重新提取

# Stage 3: 深度分析
python pipeline/run.py analyze        # 三维度并行
python pipeline/run.py analyze --stage qualitative  # 单维度

# Stage 4: 合成
python pipeline/run.py aggregate      # 4a: Frontmatter 聚合
python pipeline/run.py synthesize     # 4b: Editor-in-Chief 合成

# 前端
pnpm dev                              # Next.js 开发服务器
```

### 9.2 断点续传

- `--skip-existing`（默认开启）：检测到文件已有对应阶段字段则跳过
- `id`（SHA-256 of source URL）：全流水线唯一主键，支持跨阶段追踪
- 每阶段独立输出目录：任一阶段失败不影响前序产物

### 9.3 错误处理

| 层级 | 策略 |
|------|------|
| Agent 调用 | 指数退避重试（max 3 次，初始 2s） |
| JSON 解析 | 5 级回退策略（纯 JSON → code fence → 首尾花括号 → 行级清理 → 截断修复） |
| 单文件失败 | 失败隔离，不阻塞其他文件 |
| 单维度失败 | 成功维度照常写入，不因一个维度失败而丢弃整篇 |

### 9.4 配额与成本

| 阶段 | 模型 | 并发 | 重试 | 单篇 tokens 估算 |
|------|------|------|------|-------------------|
| Extract | claude-sonnet-4-6 | 5 | 3 | ~3K in / ~1K out |
| Analyze | claude-opus-4-7 | 3 | 3 | ~4K in / ~2K out |
| Synthesize | claude-opus-4-7 | 1 | 3 | ~38K in / ~8K out |
