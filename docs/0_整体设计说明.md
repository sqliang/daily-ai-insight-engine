## 2. 核心流程设计

#### Stage 1: 数据筛选与获取 (Ingestion)
* **思路：** 
- 轻爬虫，重筛选，将目标锁定为提供高质量 RSS 或开放 API 的源（如 Hacker News, arXiv, 科技媒体 RSS等）。
- 步骤1：基于 config.yaml 中的源配置，生成多个源 url 清单的文件。
- 步骤2：针对每个源 url 的清单，抓取对应的文章，生成带基本 Frontmatter 的 Markdown。
- Python 脚本复用一些现有且成熟的依赖工具，如 `feedparser` 抓取列表，使用 `trafilatura` 或 `readability-lxml` 提取纯文本正文。
* **输出态：** `data/raw/2026-05-07-openai-update.md`（仅包含基础 `title`, `url`, `date` 等源头元数据和正文）。

#### Stage 2: 事实抽取 (Fact Extraction )
* **你的思路：** 作为数据预处理，借助 Claude Code skill 提取事实，写回 Frontmatter。
* **评估：** 引入 Claude Code skill 是个极佳的极客思维，但**注意笔试的自动化要求**。如果它是需要人工交互触发的 CLI 工具，可能不符合“系统自动化运行”的预期。
* **优化建议：** 将其降维为一个纯 Python 异步脚本。使用 `instructor` 库配合 `pydantic` 定义事实类的 Schema（如 `corePremise`, `entities`, `epistemicStatus`）。让脚本遍历 `data/raw/` 目录，单篇调用 LLM 抽取事实，并将结果追加到对应文件的 Frontmatter 中，文件移至 `data/extracted/`。这样依然保留了 Markdown 极佳的可读性和 Debug 体验。

## 4. 汇总与可视化 (Synthesis & Dashboard)

Stage 4 splits into two sub-stages:

 Stage 4a — Frontmatter Aggregation (mechanical, no LLM):
 Read all .md files from data/03_analyzed/, extract frontmatter only (no body), produce
 per-source JSON files + one combined JSON. Fast, deterministic, zero token cost.

 Stage 4b — Editor-in-Chief Synthesis (LLM):
 A single Claude Opus call that reads the combined structured JSON and produces a
 complete daily report (top events, trends, deep dives, risks, opportunities,
 pre-computed visualization data). Output as daily-report.json + daily-report.md.
