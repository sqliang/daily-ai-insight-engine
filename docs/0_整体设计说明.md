## 2. 核心流程设计

#### Stage 1: 数据筛选与获取 (Ingestion)
* **思路：** 
- 轻爬虫，重筛选，将目标锁定为提供高质量 RSS 或开放 API 的源（如 Hacker News, arXiv, 科技媒体 RSS等）。
- 步骤1：基于 config.yaml 中的源配置，生成多个源 url 清单的文件。
- 步骤2：针对每个源 url 的清单，抓取对应的文章，生成带基本 Frontmatter 的 Markdown。
- Python 脚本复用一些现有且成熟的依赖工具，如 `feedparser` 抓取列表，使用 `trafilatura` 或 `readability-lxml` 提取纯文本正文。
* **输出态：** `data/raw/2026-05-07-openai-update.md`（仅包含基础 `title`, `url`, `date` 等源头元数据和正文）。

#### Stage 2: 事实抽取 (Fact Extraction - The Map Phase)
* **你的思路：** 作为数据预处理，借助 Claude Code skill 提取事实，写回 Frontmatter。
* **评估：** 引入 Claude Code skill 是个极佳的极客思维，但**注意笔试的自动化要求**。如果它是需要人工交互触发的 CLI 工具，可能不符合“系统自动化运行”的预期。
* **优化建议：** 将其降维为一个纯 Python 异步脚本。使用 `instructor` 库配合 `pydantic` 定义事实类的 Schema（如 `corePremise`, `entities`, `epistemicStatus`）。让脚本遍历 `data/raw/` 目录，单篇调用 LLM 抽取事实，并将结果追加到对应文件的 Frontmatter 中，文件移至 `data/extracted/`。这样依然保留了 Markdown 极佳的可读性和 Debug 体验。

### 最终完整流程蓝图 (The Playbook)

综上所述，整个系统可以完美划分为 **“离线数据处理层 (Python)”** 与 **“在线展示层 (Next.js)”**。

#### 离线调度引擎 (Python Pipeline)

```text
pipeline/
├── config.yaml          # 配置数据源 (RSS 链接等)
├── schemas.py           # 定义 Pydantic 数据结构 (事实、风控、商业等)
├── run_pipeline.py      # 核心主控脚本
```

**`run_pipeline.py` 的执行流：**
1.  **`ingest()`**: 拉取源数据 $\rightarrow$ 存入 `data/raw/*.md`。
2.  **`extract()`**: 遍历 `raw` $\rightarrow$ LLM 提取事实 $\rightarrow$ 更新 Frontmatter $\rightarrow$ 移至 `data/extracted/`。
3.  **`analyze()`**: 遍历 `extracted` $\rightarrow$ 触发 Tech/Biz/Risk 三路并发 LLM 分析 $\rightarrow$ 更新 Frontmatter $\rightarrow$ 移至 `data/analyzed/`。
4.  **`synthesize()`**: 提取所有 `analyzed` 的 Frontmatter $\rightarrow$ 喂给“主编 LLM” $\rightarrow$ 生成最终的 `frontend/data/daily-report.json`。

这套方案把所有的复杂性（API 调用、Schema 校验、重试逻辑）都锁死在了 Python 离线脚本里。在面试交付时，考官既能看到 `data/` 目录下每一步生成的 Markdown 文件（**极其直观的中间态处理逻辑展示**），又能看到 Next.js 跑起来的高大上最终页面。
