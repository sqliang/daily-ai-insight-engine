# 7. 本地数据库连接与维护指南

> 适用场景：本地开发数据库的日常使用与维护。
> 本地库 = Docker Compose 的 PostgreSQL 17（容器 `ai-insight-postgres`，端口 5433）；
> 生产库 = Neon（见 `docs/6_生产数据库配置与运维指南.md`）。

## 连接信息一览

| 项 | 值 |
|----|-----|
| 连接串 | `postgresql://postgres:postgres@localhost:5433/ai_insight` |
| 主机 / 端口 | `localhost:5433`（容器内 5432 映射到宿主机 5433，因为 5432 被占用） |
| 用户 / 密码 | `postgres` / `postgres`（仅本地，非生产凭据） |
| 数据库名 | `ai_insight` |
| 数据持久化 | Docker 命名卷 `pgdata`，容器重建不丢数据 |
| 表 | `daily_reports` / `manifests` / `articles`（drizzle 迁移管理） |

## 两个环境变量文件的分工（关键）

本项目数据库连接由两个文件分层控制，改之前先想清楚改的是哪一层：

| 文件 | 谁在读 | 指向 | 用途 |
|------|--------|------|------|
| `.env` | pipeline（python-dotenv）+ Next 兜底 | **Neon 生产库**（Direct 端点） | 每日定时任务 publish 直写生产 |
| `.env.development.local` | 仅 Next.js dev 模式（优先级高于 .env） | **本地 Docker PG** | `pnpm dev` 页面渲染毫秒级 |

规则：

- **pipeline 永远只读 `.env`**（写生产），不要为了方便把 `.env` 改回本地
- **本地开发慢 / 卡骨架屏** → 检查 `.env.development.local` 是否存在且指向 5433
- 两个文件都被 gitignore，不会提交；换机器时需各自重建

## 日常操作

### 启动 / 停止 / 状态

```bash
docker compose up -d        # 启动（restart: unless-stopped，开机自启）
docker compose ps           # 查看状态（健康检查应为 healthy）
docker compose logs -f postgres  # 看日志
docker compose down         # 停止（数据保留在 pgdata 卷）
```

### 从生产同步数据到本地（最常用）

本地 dev 看到的数据与生产有时间差，需要同步时：

```bash
DATABASE_URL="postgresql://postgres:postgres@localhost:5433/ai_insight" \
  uv run python pipeline/run.py publish --force
```

幂等 upsert，可反复执行。只同步某一天用 `publish --target-date YYYY-MM-DD`（去掉 `--force`）。

### 查询数据（本机未装 psql）

```bash
# 方式一：容器内 psql（推荐，零安装）
docker exec -it ai-insight-postgres psql -U postgres -d ai_insight \
  -c "select count(*) from articles;"

# 方式二：Node 脚本（项目依赖 postgres.js 现成）
node -e "
const sql = require('postgres')('postgresql://postgres:postgres@localhost:5433/ai_insight', {prepare:false});
sql\`select count(*)::int n from daily_reports\`.then(r => { console.log(r[0]); return sql.end(); });
"
```

### 表结构变更（drizzle 迁移）

schema 改动后（`src/lib/db/schema.ts`）：

```bash
pnpm drizzle-kit generate   # 生成新迁移文件到 drizzle/
# 应用到本地库
DATABASE_URL="postgresql://postgres:postgres@localhost:5433/ai_insight" pnpm drizzle-kit migrate
# 应用到生产库（用 Neon Direct 端点）
DATABASE_URL="<Neon Direct 连接串>" pnpm drizzle-kit migrate
```

### 清空重建（慎用）

```bash
# 连数据卷一起删除，彻底重置（不可恢复）
docker compose down -v
docker compose up -d
DATABASE_URL="postgresql://postgres:postgres@localhost:5433/ai_insight" pnpm drizzle-kit migrate
DATABASE_URL="postgresql://postgres:postgres@localhost:5433/ai_insight" \
  uv run python pipeline/run.py publish --force
```

## 排障速查

| 现象 | 排查 |
|------|------|
| 页面卡骨架屏、接口几十秒 | `.env.development.local` 是否缺失/被删；当前 dev 是否在读远程 Neon |
| `pnpm dev` 报 DATABASE_URL 未配置 | 两个 env 文件都不存在或都没配 `DATABASE_URL` |
| 连接被拒（ECONNREFUSED 5433） | `docker compose ps` 看容器是否在跑；`docker compose up -d` 启动 |
| 端口冲突 | 5433 被占：改 `docker-compose.yml` 端口映射与 env 文件连接串，保持一致 |
| 本地数据与生产不一致 | 跑上面的"从生产同步数据到本地" |
| 容器在但查询报错（表不存在） | 跑 `pnpm drizzle-kit migrate`（带本地 DATABASE_URL） |
| 怀疑数据损坏 | 清空重建（见上），生产数据在 Neon 不受影响 |
