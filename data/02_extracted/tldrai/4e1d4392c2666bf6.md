### Description

This workshop covers the architectural shift from general-purpose to domain-specific agents, part of the Building Agentic Systems on AWS series. Register for the workshop, then explore the companion guide for additional context on the topics covered in this workshop.

A general-purpose agent applied to a specific domain tends to be inconsistently reliable. It handles the common case and fails subtly at the edges: the recommendation that ignores context, the route that looks valid but violates a geofence, the voice response that arrives 400ms too late. These failures share a root cause. The agent wasn't scoped to the domain. It has no curated knowledge, no domain-specific tools, no guardrails that enforce the constraints that domain actually requires. This workshop shows how to fix that across three production domains, using AWS services and tools from across the AI landscape, available through AWS Marketplace.

### What you'll learn

**The four levers of domain specialization:**system prompt engineering, knowledge corpus curation, tool selection, and guardrail design.**Customer engagement agents that personalize at the edge:**domain-scoped retrieval corpora, brand-safe output constraints, and engagement-specific evaluation criteria that catch subtle tone and context failures.**Location-aware logistics agents grounded in geospatial reasoning:**geocoding, route optimization, and geofencing as scoped agent tools with freshness-aware data strategies that prevent stale-map failures.**Voice-enabled agent pipelines with low-latency constraints:**streaming speech-to-text, interruption handling, and voice-specific output constraints that keep conversations natural under real-time pressure.
