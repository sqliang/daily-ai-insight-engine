key_logic_flow:
- Assembly Hall of Shame 由安全研究者 Christopher Domas 发起，与常规指令延迟优化相反，专门寻找单条 CPU 指令执行延迟的绝对下限，并维护一个最慢指令排行榜。
- 排行榜基准条目显示 nop 仅耗时 1 周期、rdtsc 为 49 周期，而通过 fxrstor64 从 PCIe MMIO 高延迟区域加载 512 字节 FPU/MMX/XMM
  状态，可将单指令延迟提升到数亿乃至数十亿周期。
- 当前最高纪录为 198,002,498,236 周期、耗时约 62 秒，实现方法是在 fxrstor64 加载期间让多个锤击核心对另一个高延迟 MMIO 寄存器进行紧密
  4 字节读取，饱和 PCIe 根复合体与端点的事务队列。
- 项目使用 mmiotic、project:nightshyft、rakefield 等工具自动扫描 PCIe 死区、高延迟 MSR 与 CPUID leaf，例如
  VIA 未文档化的 0x133 MSR 读取耗时 161,602 周期。
- 部分条目揭示了硬件安全影响，例如用跨缓存行边界的 lock 指令迫使 CPU 走外部总线锁路径，以及用非对齐 ymm0 MMIO 加载破坏系统管理模式（SMM）的
  smiiiiiiiiiiiiiiii 攻击。
- 文章预告了在 Sapphire Rapids 上利用 xrstor64 加载约 8KB AMX 状态（约为 fxrstor64 的 16 倍）的目标，预计可将单指令延迟推高到约
  1 万亿周期。

Instruction latency analysis usually focuses on performance
*optimization*—making code run as fast as possible. The `Assembly Hall of Shame`

takes the opposite approach: searching for the absolute floor of
single-instruction performance.

**Strategy**: Use `fxrstor64`

to load 512-byte FPU/MMX/XMM state from a
high-latency MMIO region in the PCIe fabric, then starve the fabric while the
load is in flight — a fleet of hammer cores pounds a different high-latency
MMIO register with tight 4-byte reads, saturating the PCIe root complex and
endpoint with non-posted transactions, so CPU 0's 512-byte `fxrstor64`

must
queue behind all that contending traffic.

**Contender**: AMD Ryzen 7 5800H

```
; CPU 0 — timed instruction
movl $0xfcc68830, %rsi
fxrstor64 %rsi
; CPUs 1..N — hammer loop against a different high-latency location
movl 0xfcc68858, %eax
```

🏆 **Score**: 198,002,498,236 cycles

🏆 **Time**: 62 seconds

A spec-violating unaligned ymm0 load that forced non-posted dword transactions from stalled GPU registers was used to break the fundamental design of System Management Mode in smiiiiiiiiiiiiiiii.

`vmovdqu 0xfcc003b1, %ymm0`

- Instructions may use whatever setup is necessary, but only a single instruction is eligible to be scored.
- Trapped/emulated/virtualized instructions may only time the trap, not the handler.
- Instructions must not be interruptible.
`rep movs`

,`pause`

, etc. are disqualified. - Times are normalized based on the CPU base clock frequency.
- All platforms must be in their factory stock configurations - no hardware modifications.
